# 部署到 Cellapp：编码 Agent 指引

[English version](./AGENTS.md)

用户希望把当前项目开发并部署到 Cellapp。由你自行运行官方已发布的客户端，完成构建、上传和验证。用户只需在浏览器中批准设备授权。不要自行实现 Cellapp 的上传协议，也不要让用户安装 CLI。

## 检查项目

在用户的项目目录中工作。读取包清单、锁文件、构建脚本、静态输出，以及已有的 `cellapp.json`。确定可用的构建命令，以及包含 `index.html` 的输出目录。普通 HTML 如果不需要构建，就省略构建命令。仅当应用使用客户端路由时添加 `--spa`。再次部署时复用 `cellapp.json` 中的应用关联。只有构建命令或输出目录确实不明确时才询问。

Cellapp 托管静态前端文件，不运行 Next.js SSR、自定义服务器、Serverless 函数或私有后端。如果项目需要服务器，应说明障碍；仅在不改变预期行为时，才准备真正的静态导出。不要把私密凭证放进打包后的前端文件；获准访问的访客可以读取这些文件。

## 需要开发界面时

如果任务包含开发或大幅重新设计应用，而用户没有提供 UI 方向，阅读[用户应用设计指导](./app-design.zh-CN.md)，直接将其作为可调整的默认建议使用，不要询问用户是否启用。用户明确的设计要求和项目已有约定优先。根据应用需求自行选择框架与样式方案；指导不要求特定工具，也不要求采用 Cellapp 的品牌外观。如果任务只是部署现有应用，直接继续部署流程，不必重新设计。如果暂时无法读取设计指导，仍遵循这些优先规则并继续完成任务。

## 按需运行已发布客户端

确认 Node.js 至少为 22.12，且 npm 可用。在项目目录中验证官方已发布的包：

```sh
npm exec --yes --package=@cellapp/cli@latest -- cellapp --help
```

后续所有命令沿用 `npm exec --yes --package=@cellapp/cli@latest -- cellapp` 前缀。npm 会按需获取并缓存该包，无需全局安装。如果 Node.js 或 npm 不可用、包获取失败或帮助命令验证失败，应报告具体障碍。不要使用 `sudo`、关闭 TLS 验证，或从未经验证的来源安装。

客户端默认连接 `https://cellapp.ai`。它会迁移来源恰好为已停用地址 `https://console.cellapp.ai` 的项目关联，并保留应用 ID 和待完成部署 ID；显式指定旧来源会被拒绝。对于用户或环境提供的其他自定义来源，应予以遵循。旧凭证不会被复制：请用户在此设备上重新批准一次浏览器授权，此后该所有者的项目可复用新的用户级凭证。不要将凭证写入项目文件或日志。

## 构建、授权和发布

使用项目实际的输出目录和构建命令，例如：

```sh
npm exec --yes --package=@cellapp/cli@latest -- cellapp deploy --project . --output dist --build 'npm run build'
```

不需要构建的普通 HTML 省略 `--build`。客户端在本机构建、校验静态文件、上传，并原子发布。如果启动设备授权，将验证网址和代码交给用户，在用户通过浏览器批准期间保持命令运行。不要索取密码、Cookie、访问密钥或部署凭证；聊天中的回复不等于浏览器批准。

仅当 CLI 返回 `status: published` 时才报告发布成功。给出应用地址，并说明访客仍需完成的访问步骤。首次部署可能只返回一次访问密钥：仅交给提出请求的所有者，不要写入 URL、仓库、Issue 或项目文件。公开应用的访客仍需登录 Cellapp；受限应用还需要所有者批准或兑换访问密钥。

## 失败恢复与扩展

构建失败时，修复项目后重跑同一命令。暂时性上传或网络失败时，对同一命令重试一次；待完成的部署状态可以复用。再次失败后，报告错误和当前状态。不要通过删除应用、更换 slug 或虚构新的应用关联来掩盖失败。遇到 `app_data_not_ready`，先查看 `cellapp data status --project .`；服务恢复健康后使用 `cellapp data reconcile --project .`，再重试部署。

如果需要持久化应用数据表，按照 [Cellapp 部署 Skill](https://github.com/cellapp-ai/skills/blob/main/skills/cellapp-deploy/SKILL.md) 中独立的计划、应用和验证流程操作。仅保存在浏览器本地的数据不会跨设备同步。Cellapp 当前提供静态发布和受控应用数据表；结账和付费应用销售不属于本部署流程。
