# 设计规范

适用范围：Cellapp 官网页面、组件、交互和品牌展示。基线日期：2026-09-28；品牌资产更新：2026-09-29。来自当前 `site.css`、`refinements.css` 与页面实现。规则含义见 [规范入口](./README.md)。

## 1. 设计方向

核心表达是“完成静态构建后，用简洁流程获得可分享链接”。页面使用深色背景、荧光绿主强调、蓝色辅助强调、终端示意和编辑式排版，强调工程清晰度与可靠交付。

- 首页强调产品价值和工作流；价格帮助比较；文档帮助完成任务；文章优先保证长文阅读。
- 新页面沿用共享导航、Footer、色彩、字体与按钮层级，用内容组织形成差异。
- 终端示意只展示工作流，不伪装成正在发生的真实部署。
- 装饰必须服务信息层级；避免大面积渐变、过量浮层、重复卡片或连续动画遮盖正文。
- 当前只有深色官网设计基线；Tailwind 中存在主题配置并不代表官网已实现主题切换。

## 2. 品牌资产

品牌资产统一存放于 `public/logos/`。文件名使用 `cellapp-<方向>[-light].<格式>`；`-light` 表示适用于浅色背景，图形为黑色；无后缀版本图形为白色，适用于深色背景。

| 场景 | 资产 | 背景与使用方式 |
| --- | --- | --- |
| 深色导航与 Footer | [cellapp-landscape.svg](../../public/logos/cellapp-landscape.svg) | 493 × 100，透明背景白色横向 `ce//app` 字标，使用内嵌 `wordmark` |
| 浅色横向展示 | [cellapp-landscape-light.svg](../../public/logos/cellapp-landscape-light.svg) | 493 × 100，透明背景黑色字标 |
| 方形图标与静态导出 favicon | [cellapp-square.svg](../../public/logos/cellapp-square.svg) | 1024 × 1024，黑底白色六边形 C 与双斜线，使用内嵌 `logo` |
| 浅色方形展示 | [cellapp-square-light.svg](../../public/logos/cellapp-square-light.svg) | 1024 × 1024，白底黑标 |
| 方形位图导出 | [cellapp-square.png](../../public/logos/cellapp-square.png)、[cellapp-square-light.png](../../public/logos/cellapp-square-light.png) | 两种配色均为 1024 × 1024 PNG，分别保留黑底和白底 |
| 深色竖直堆叠展示 | [cellapp-portrait.svg](../../public/logos/cellapp-portrait.svg) | 400 × 440，透明背景白色图形，上方 `c//` 图标、下方 `cellapp` 字标 |
| 浅色竖直堆叠展示 | [cellapp-portrait-light.svg](../../public/logos/cellapp-portrait-light.svg) | 400 × 440，透明背景黑色图形，上方 `c//` 图标、下方 `cellapp` 字标，相同堆叠构图 |

原 `public/logo-horizontal.svg` 已迁移为 `public/logos/cellapp-landscape.svg`，原 `public/logo.svg` 已迁移为 `public/logos/cellapp-square.svg`，不再保留旧路径。`public/favicon.svg` 与 `public/icons.svg` 均为 `cellapp-square.svg` 的黑底白标副本，作为根路径图标入口；修改 square 来源时须同步这两个文件。交付页面继续使用内嵌 square SVG。

横向与竖版字标均由 Michroma 字形转为矢量轮廓，不需要运行时下载字体。导航字标当前宽 180 px，移动端 156 px，保持原始比例；Brand 链接最小高度 44 px。

- 不拉伸、旋转或自行重排已定义的 Logo 构图，不用普通文本替代现有矢量字标。需要竖直排列时直接使用 portrait 版本。
- 竖版复用 square 的 `c//` 图标轮廓；下方字标使用同一 Michroma 字体的 `cellapp`，其中 `ll` 为直立小写字母，不使用横向字标的 `//`。图标在上、字标在下并居中，不含方形版本的底色矩形。
- 浅色展示使用 `-light` 版本，深色展示使用无后缀版本；方形版自带不透明底色，横向与竖版背景透明。
- 保持足够背景对比，避免把细字标放在复杂图像上。
- 新布局建议周围保留至少 12 px 净空；这是本次建立的排版建议，现有资产未定义正式品牌净空单位。
- Brand 链接保留可访问名称，例如 `Cellapp home`。
- 品牌资产改变时同步原始 SVG、内嵌表示及对应展示检查。

SVG 是可编辑来源，PNG 是供不支持 SVG 的渠道使用的导出副本。方形 PNG 从对应 SVG 渲染，不单独修改。具有 librsvg 工具的环境可在项目根目录重新导出：

```sh
rsvg-convert --width 1024 --height 1024 --output public/logos/cellapp-square.png public/logos/cellapp-square.svg
rsvg-convert --width 1024 --height 1024 --output public/logos/cellapp-square-light.png public/logos/cellapp-square-light.svg
```

`src/logo.ts` 中的 `logo` / `wordmark` 分别由 square / landscape SVG 的原始字节进行 Base64 编码生成，更新来源时须同步。正式构建会将 `public/logos/` 复制到 `dist/logos/`，托管时这些资产通过 `/logos/<文件名>` 访问；单文件页面继续使用内嵌资产。

## 3. 官网颜色

| Token | 当前值 | 用途 |
| --- | --- | --- |
| `--ink` | `#090d18` | 页面背景、亮按钮上的深色文字 |
| `--panel` | `#111827` | 终端、代码、辅助内容面板 |
| `--paper` | `#f5f7f2` | 标题与主要文字 |
| `--muted` | `#9ba5b7` | 简介和次级正文 |
| `--line` | `#293142` | 结构分隔线和常态边框 |
| `--lime` | `#b6ff5c` | 主要 CTA、焦点、选中状态、命令强调 |
| `--blue` | `#8199ff` | 次级标签、少量辅助装饰 |

主按钮采用 lime 背景和 ink 文字；次按钮采用透明背景、line 边框和 paper 文字。阅读正文不能直接用强调色铺满。

终端注释和 ticker 当前最终颜色为 `#a0acc0`，文章 metadata 为 `#aab6cb`，长文正文为 `#c5cbd6`。这些由后载入的样式覆盖，不能退回原先更暗的辅助文字值而不检查可读性。

官网 HEX token 与基础组件 HSL token 尚未完全统一。新增组件必须检查最终渲染的背景、文字、边框与焦点颜色；通用 token 整理作为独立工作处理，不在新增页面时静默改变全站配色。

颜色不能单独承担状态含义：套餐推荐同时有文字，计费选中同时有 `aria-pressed`，当前导航同时有结构和语义标记。

## 4. 字体与文字层级

| 类型 | 当前基线 | 使用要求 |
| --- | --- | --- |
| 正文、标题、按钮 | Space Grotesk，回退 system-ui / sans-serif | 保持标题与正文的层级差异 |
| 命令、标签、状态 | DM Mono，回退 monospace | 用于工程信息和短标签，避免整篇正文等宽排版 |
| Logo | Michroma 矢量轮廓 | 不作为正文运行时字体 |
| 默认 h1 | `clamp(3.4rem, 7.2vw, 6.5rem)`，行高 0.92 | 面向短标题，必须检查长标题换行 |
| 默认 h2 | `clamp(2.6rem, 5vw, 5rem)`，行高 0.96 | 用于营销区块，文档与文章按阅读场景覆盖 |
| h3 | 1.35 rem | 子主题和步骤标题 |
| 首页介绍 | 1.15 rem，行高 1.65 | 控制行长，保留 CTA 上下留白 |
| 文档正文 | 行高 1.7，最大宽度 720 px | 易扫描的段落与步骤 |
| 文章正文 | 1.05 rem，行高 1.85 | 优先长文阅读 |
| 代码 | 14 px，行高 1.8 | 保留空白，容器内部横向滚动 |

首页标题与文章标题有独立响应式覆盖，不得强制所有页面使用一个固定字号。默认标题字距较紧，新增长标题需人工检查可辨性，不机械套用短营销标题的换行。

字体由本地 fontsource 资源生成内嵌样式：Space Grotesk 400 / 500 / 600 / 700，DM Mono 400 / 500，`font-display: swap`。当前只嵌入 Latin 字符子集；若新增中文等语言，必须检查实际回退字体和版面，不能声称已内嵌相应字形。

## 5. 布局、间距与形状

| 模式 | 桌面基线 | 800 px 及以下 |
| --- | --- | --- |
| `.wrap` | 最大 1180 px，两侧至少 24 px | 最大 600 px，两侧至少 18 px |
| 导航 | 高 78 px，横向导航 | 最小高 72 px，菜单展开后自适应 |
| 首页 Hero | 双列，间距 64 px | 单列，间距 50 px，取消终端旋转 |
| 营销 section | 上下 110 px | 上下 90 px |
| 工作流 | `.8fr 1.2fr`，间距 100 px | 单列 |
| 资源区 | 三列，间距 40 px | 单列，间距 25 px |
| 文档 | 270 px 侧栏，间距 80 px | 侧栏变顶部换行目录 |
| 套餐 | 三列，间距 14 px | 单列 |
| 博客 | 两列，间距 16 px，首篇跨列 | 单列 |
| 长文 | 最大正文宽度 760 px | 随容器收缩 |

间距优先复用相邻模式。新组件建议采用 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 px 等间距尺度；现有页面包含 14、18、25 等值，尚未实施统一 spacing token，不能为对齐建议而全站改值。

按钮通常为 5 px 圆角，代码面板 6 px，终端 8 px；保留克制的圆角。分隔线承载区块结构，减少不必要的阴影。终端保留少量蓝色偏移阴影与桌面倾斜；价格推荐卡采用 lime 边框及轻量偏移阴影。

## 6. 页面模式

### 首页

顺序保持“价值承诺 → 终端示意 → 产品优势 → 三步工作流 → 价格 / 文档 / 博客入口 → 最终 CTA”。第一屏主次操作明确，终端不抢占主标题和操作。静态能力条只表达可说明的产品特征。

### 价格

先展示 Plan preview，再提供计费周期切换、三个套餐、真实表格和 FAQ。推荐套餐只突出一个；价格必须同时说明计费单位和年付总额，切换不能只更新大数字而保留旧说明。

套餐操作打开带选择上下文的文档。文案不得暗示立即支付、创建账户或订阅成功。草案标识必须靠近比较内容，不能只藏在 Footer。

### 文档

PageHero 说明任务，目录提供章节锚点，正文按介绍、步骤、命令、下一节组织。桌面目录可 sticky，移动目录可换行。代码面板将标签与复制操作放在顶栏；正文完整可读，不以折叠或脚本加载作为阅读前提。

### 博客列表与文章

列表首篇可使用跨列重点展示，其余卡片强调标题、摘要、类别、日期与阅读时长。重点卡采用 panel 背景，不恢复已被覆盖的渐变。

详情页展示返回入口、metadata、独立标题、摘要、分节正文和后续操作。每篇文章必须有独立完整正文，不能用一个占位页面承接所有卡片。

## 7. 交互与状态

| 元素 | 必须表达的状态 / 行为 |
| --- | --- |
| 导航 | 当前页面可辨识，`aria-current="page"` 对应当前路由 |
| 移动菜单 | 关闭 / 展开可操作，按钮名称与 `aria-expanded` 同步 |
| 主次按钮 | 正常、hover、focus 可区分；行为由文字明确表达 |
| 计费周期 | 月付 / 年付互斥，选择状态通过 `aria-pressed` 表达 |
| 文档目录 | 当前可见章节及锚点目标一致 |
| 复制命令 | 成功提示和失败后手动复制提示，复制内容精确 |
| 推荐套餐 | 边框、文字共同强调，避免只有颜色 |

现有按钮 hover 上移 2 px，文章卡 hover 上移 4 px，过渡约 0.2 秒。新动效保持克制并适配 `prefers-reduced-motion`；减少动态效果时禁用平滑滚动和非必要过渡。新建 loading、empty、error 或 disabled 状态时，必须有真实行为需要和对应说明；当前官网没有远程内容加载流程，不展示虚假的加载状态。

## 8. 响应式与可访问性要求

- 至少检查 320、390、768、1440 px；800 px 是现有断点，检查断点两侧时建议补看 800 / 801 px。
- 页面不允许整体横向溢出；代码和表格可在自身容器内横向滚动。
- 长标题、套餐名称、链接和代码须在小屏保持可读；不能用隐藏主要内容解决空间不足。
- JavaScript 不可用时导航与正文仍可读可用；移动端显示真实导航，隐藏无法工作的菜单按钮。
- 焦点必须可见。现有全局 focus outline 为 2 px lime、offset 4 px，复制按钮 offset 3 px；局部基础组件可采用等效可辨识焦点。
- 键盘能到达主要操作，状态切换可被辅助技术感知；保留跳过正文入口。
- 以 WCAG 2.1 AA 为可访问性目标：普通文字对比度至少 4.5:1，大号文字至少 3:1；大号文字按至少 18 pt 或粗体 14 pt 判断。参见 [W3C 文字对比度说明](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum.html)。关键控件边界和状态也要检查可辨识程度。这是验收目标，不表示网站已经获得完整合规认证。
- 建议触控目标至少 44 × 44 px；当前部分小按钮和文字链接尚未统一达到这个建议，新控件优先遵循并为紧凑布局说明取舍。
- 不只靠 hover 提供信息；图片有恰当替代文本，表格有表头和说明，heading 结构反映内容。
- 自动 axe 通过后仍需人工检查焦点顺序、缩放、长文阅读和视觉层级。

## 9. 文案规范

使用简短、具体、可操作的英文界面文案，围绕“构建、部署、检查、分享”说明下一步。避免未经证实的数字、客户评价、性能或安全保证。命令示例保留真实可复制文本，示意内容明确标识。

价格草案、无结账能力和未发布版本化 API 等限制应出现在对应任务附近。工程构建细节留在仓库文档；只有帮助访客完成使用任务的技术信息才放进官网。

## 10. 设计验收与待改进项

- [ ] 主次信息清晰，页面符合对应内容模式。
- [ ] Logo 比例、字体和颜色沿用基线，未引入隐式远程字体依赖。
- [ ] 桌面、小屏和长内容布局正常，局部滚动不扩散成页面溢出。
- [ ] hover、focus、选中、复制反馈与无脚本状态可用。
- [ ] 减少动态效果、键盘导航和可访问语义已检查。
- [ ] 草案和示意标识清楚，CTA 目的地与实际能力一致。

当前未统一设计 token 命名、间距变量和所有控件触控尺寸，也没有视觉快照差异门禁。后续完善时优先解决影响可读性、交互和维护的缺口，不能仅为形式统一破坏现有页面。
