# 代码规范

适用范围：应用源码、构建与验证脚本、样式和配置。基线日期：2026-09-28；结合 [项目规范](./project.md) 与 [设计规范](./design.md) 使用。

## 1. 可读性与组织

- 应用使用 TypeScript / TSX、函数组件和 hooks。命名表达职责，避免仅反映实现细节的缩写。
- 组件和类型使用 `PascalCase`，函数、变量和 hooks 使用 `camelCase`，hook 名以 `use` 开头；CSS 类沿用 `kebab-case`。
- 页面级组件优先放在明确的页面模块，站点框架和共享内容模式放在业务组件中，通用 UI 原语放在 `components/ui/`。这是后续拆分方向，当前页面仍集中在 `App.tsx`。
- 内容放在 `content.ts`；不要把套餐数字或文章正文复制进多个视图。暂不要求抽取每句固定界面文案。
- 新增手写 TS / TSX 代码建议两空格缩进、单引号、分号、多行 JSX；邻近文件采用其他风格时保持局部一致。仓库目前没有统一格式化工具，不能宣称格式已被自动强制。
- 注释解释原因、兼容限制、单位和边界，避免重复代码含义。不要为了满足行数限制进行机械拆分。

## 2. TypeScript 与导入

- 业务数据和组件 props 必须有明确类型；状态集合优先使用字符串联合类型，例如 `Cadence`。
- 使用 `import type` 导入纯类型，保持与 `verbatimModuleSyntax` 一致。
- 共享模块优先使用现有 `@/` 别名，邻近模块可使用相对路径；跨构建工具调整别名时同时检查 TypeScript、Vite 和 Parcel。
- 不使用 `any` 绕过未知值校验；外部输入优先从 `unknown` 收窄。类型断言只用于已经证明的边界，不把断言当作运行时验证。
- 非空断言必须有可说明的不变量，例如静态入口始终提供 `#root`；对于可变 DOM 或查询参数必须处理缺失值。
- 不关闭 `strict`、未使用检查或 hooks 规则来消除错误；先修复原因。

当前应用 TypeScript 配置启用 `strict`、`noUnusedLocals`、`noUnusedParameters`、`noFallthroughCasesInSwitch` 和 `erasableSyntaxOnly`。使用与这些配置兼容的语法。

**检查边界**：`tsconfig.app.json` 的入口是 `src/main.tsx`，编译器检查它及其导入链；未被导入的 UI 文件不因此得到完整类型检查。`tsconfig.node.json` 包含 `vite.config.ts`；`scripts/export-static.tsx` 不在当前项目类型检查入口内。把基础组件接入应用前必须处理实际编译问题，新增脚本不能仅以“主应用类型检查通过”证明其类型正确。扩大覆盖范围属于后续工具变更。

## 3. React 组件与状态

- hooks 在组件或自定义 hook 顶层调用，不按分支、循环或回调调用。
- 使用稳定数据标识作为列表 `key`，例如 `plan.id`、`article.slug`、`doc.id`；可重排列表不得使用数组索引。
- 一个状态只保存无法从 props 或现有数据计算的值；价格、年费和节省比例由数据推导。
- 副作用放在 `useEffect`；观察器、监听器、定时器必须清理。当前文档观察器需要保留 `disconnect()`。
- 组件渲染保持纯函数行为；不要在渲染期间执行请求、修改 DOM 或写存储。
- 抽象围绕实际复用：共享 Header、Footer、PageHero、CodeBlock 有明确职责；避免仅使用一次、没有独立含义的组件层级。
- 正常情况不添加 `memo`、`useMemo` 或 `useCallback`；存在可测量的重复工作或引用稳定需求时再使用。

## 4. 静态渲染与 hydration

`App` 既由浏览器调用，也被 `scripts/export-static.tsx` 通过 `renderToString` 调用。

- 模块顶层和服务端渲染路径不得直接访问 `window`、`document`、`navigator` 或未保护的 `location`。
- 浏览器 API 放在事件处理器或 effect 中；无法延迟时使用明确的环境判断。
- 同一路由的服务端输出与浏览器首次渲染必须一致，避免随机数、当前时间、浏览器尺寸等导致 hydration 差异。
- 查询参数引起的浏览器专属状态在 effect 中应用；保留价格默认月付、菜单默认关闭等确定初始状态。
- HTTP 模式在已有 HTML 与 `data-route` 匹配时 hydrate；本地文件模式重新挂载。更改入口必须分别验证这两条路径。
- 核心文字、导航和链接必须出现在静态 HTML 中；JavaScript 负责交互增强。

## 5. 链接、路由与输入边界

- 导航使用真实 `<a href>`，行为使用 `<button>`；不要用 `div` 点击事件代替语义元素。
- 新的站内跨页链接优先复用现有 Link 行为，在 `file:` 下转换为 `?page=`；章节跳转使用真实 `#id`。
- 路由以 `routePaths` 和页面实现为依据。新增路由同时维护解析、静态导出和 metadata，不只增加一个导航项。
- 外链开新窗口时保留适当 `rel`，标签清晰说明目的；内容链接来源必须可信。
- `plan`、`cadence` 等参数先与已知数据 / 允许值匹配；未知值不能变成未验证的产品状态。
- 当前路由解析仍有较宽的兜底匹配。后续新增复杂路由时建议显式匹配完整路径，并验证未知路径；不要把当前兜底视为严格路由校验。
- 静态服务器保留目录越界保护；导出模板中的 metadata 必须转义。

## 6. 内容模型与日期

沿用 `Plan`、`DocSection`、`Article` 等已有模型，新增字段必须说明含义并调整所有消费处。

- slug 和章节 id 使用稳定、唯一、适合 URL 的小写标识；新增文章建议 `kebab-case`，避免 `/`、`..` 或查询字符。
- 日期保存为 `YYYY-MM-DD`，展示保持确定时区；当前文章使用 `en-US` 和 `UTC` 格式化。
- `monthly` 为月付价格，`yearly` 为按年付费的月均价格；单位不能隐式改变。
- 文章标题、摘要、正文、metadata 与路由须对应同一条数据。
- 当前内容用 React 文本节点输出；不得未经净化引入用户 HTML 或 `dangerouslySetInnerHTML`。
- 手写数据也要检查唯一性、有效日期和非空正文；TypeScript 不会自动验证这些内容约束。

## 7. CSS 与组件样式

当前导入顺序为 `index.css` → `fonts.css` → `site.css` → `refinements.css`。官网 CSS 存在同名选择器的覆盖，`--muted` 同时被基础 HSL token 和官网 HEX token 使用。

- 修改样式前沿导入顺序检查同名规则与最终计算样式，不把单个文件中的值当成最终结果。
- 颜色、边框和主要状态优先使用官网变量；新增通用组件时检查 Tailwind HSL token 是否与官网变量兼容。
- 不继续扩大同名不同格式变量的冲突。统一变量命名与迁移属于独立重构，不能悄悄改值影响全站。
- 新规则使用可读的多行结构，放在相关模块；避免为一个局部问题不断追加全局覆盖。
- 不新增无理由的 `!important`；已有特殊覆盖修改时说明层叠关系。
- 响应式以当前 800 px 断点为基础，保持内容优先；不要仅按某一设备名称分支。
- 栅格子项需要时使用 `min-width: 0`；长代码和对比表在容器内部滚动，不让整页产生水平滚动。
- 保留 focus、无 JavaScript 和 reduced-motion 样式；新动效也必须支持减少动态效果。

## 8. 可访问交互与错误处理

- 每页一个主要 `h1`，按结构组织 `h2` / `h3`；保留 `<main>`、导航名称和跳过正文链接。
- 导航状态使用 `aria-current`；移动菜单使用 `aria-expanded` 与 `aria-controls`；计费按钮使用 `aria-pressed`。
- 状态变化提供可感知反馈。复制成功 / 失败使用 status 区域，不能只改颜色。
- Clipboard API 可能失败，保留手动复制的替代路径；成功提示只能在复制完成后显示。
- React 文档 effect、复制和静态服务器错误分别按用途处理，不用空 `catch` 隐藏故障。
- 用户提示说明可恢复步骤；开发和构建失败提供可定位信息，不泄露凭证。
- 代码块使用 `pre` / `code`，比较表使用真实表头与 caption，日期使用 `time`。

## 9. 资源、脚本与依赖

- `public/logos/cellapp-square.svg` 和 `public/logos/cellapp-landscape.svg` 是原始资产；`src/logo.ts` 是供单文件输出使用的内嵌表示，修改时同步验证内容一致。
- `src/fonts.css` 通过 `embed-fonts.mjs` 生成，不能靠手工修改生成文件交付字体调整。
- 新资源要检查静态导出后的引用方式，不能只验证 Vite 开发环境中的路径。
- 构建脚本明确输入和输出，临时结果留在 `.build/`；失败必须以非零退出码结束。
- Node 脚本优先沿用 `.mjs`；当前测试脚本为 `.cjs`，新增脚本遵循相应模块边界。
- 使用 pnpm 添加 / 删除依赖并同步锁文件；不引入第二份 lockfile，不在 build 里临时安装包。
- 不因模板目录已有某库就扩大实际依赖使用。新增依赖说明必要性及对单文件体积的影响。
- 凭证不得写入源码、静态内容、浏览器环境变量或交付 HTML；构建期嵌入前端的值视为公开值。

## 10. 检查与评审

当前 Oxlint 配置使用 react、typescript、oxc 插件，hooks 规则为 error，组件导出规则为 warn；告警不一定阻断命令，但新变更应处理相关告警。

评审重点：

- [ ] 类型和数据单位清晰，输入已收窄，没有绕过检查。
- [ ] 组件能被静态渲染，首次渲染确定，副作用有清理。
- [ ] 链接同时适用于 HTTP 与单文件模式，metadata 和路由同步。
- [ ] 样式复用基线，移动布局、焦点及无脚本状态可用。
- [ ] 正常、失败和恢复路径可理解，操作结果与提示一致。
- [ ] 依赖、生成文件和源文件职责清楚，验证覆盖受影响行为。

验证应覆盖可观察行为，不编写仅重复实现细节的测试。当前没有独立单元测试框架，也没有全库格式化、脚本类型检查或 CI 门禁；这些都是工具缺口，不能通过文档表述为已自动执行。
