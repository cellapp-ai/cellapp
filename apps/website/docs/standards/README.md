# Cellapp 项目规范

本目录是 Cellapp 官网的协作规范入口，面向开发、设计、内容维护和评审。基线日期：2026-09-28；依据当前源码、构建脚本、验证脚本和已有 OpenSpec 变更整理。

| 文档 | 适用场景 | 主要内容 |
| --- | --- | --- |
| [项目规范](./project.md) | 开始任务、调整范围、构建与交付 | 项目边界、目录职责、静态路由、内容维护、验证与发布 |
| [代码规范](./code.md) | 编写和评审源码、脚本、样式 | 类型、组件、渲染、链接、数据、CSS、依赖和错误处理 |
| [设计规范](./design.md) | 新增页面、调整布局、更新视觉资产 | 品牌、颜色、字体、栅格、页面模式、交互、响应式和可访问性 |

## 如何使用

1. 开始任务时阅读项目规范，再阅读受影响领域的规范。
2. 在变更说明中写明目标、影响页面和验收方式；涉及规范例外时说明原因与取舍。
3. 完成后按项目规范中的检查清单交付，行为改变时同步更新相关文档与 OpenSpec 要求。

## 规则的含义

- **现状**：从当前文件可核实的事实，不表示它是长期最优方案。
- **必须 / 不得**：本次建立的后续变更要求；未配备自动检查的条目通过评审和人工验收执行。
- **建议 / 优先**：默认做法，可以在说明理由后采用其他方案。
- **待改进**：已经发现但本次没有修改的实现或工具缺口，不得描述为已经完成。

这些文档只建立协作约定，不会自动修改编译配置、样式、测试或产品行为。版本与执行命令以 `package.json`、锁文件及脚本为准；产品行为以可复现实现和对应需求为依据。发现冲突时记录并同步修正规范，不能仅凭文档宣称功能已实现。

更新其中一份文档时检查其他文档的引用和相同约定，避免重复维护出不同结论。新增工具、后端、CMS、支付、路由机制或品牌系统时应重新评估本目录的适用范围。
