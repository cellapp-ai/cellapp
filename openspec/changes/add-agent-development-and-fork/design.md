# Design

## Context

见 [proposal.md](proposal.md)。首版保留本机 `cellapp doctor`、Agent CLI 首选项与静态发布，也已写入但未开放设备、项目、任务试验性表与源码。现有部署授权 `/auth/device` 签发的是管理应用的 CLI 凭证，不能拿来控制用户电脑。个人模型连接只为当前应用访客授权；本机编码 Agent 可以继续使用自己的账号、订阅和 CLI 登录。

## Goals / Non-Goals

**Goals:**

- 让通用开发任务与 fork 后副本共用明确的设备、项目和执行权限边界。
- 保证远程任务的可恢复状态、本机未提交工作的保护、私有预览和确认发布的可核验性。
- 让包与个人副本拥有独立版本和秘密生命周期。

**Non-Goals:**

- 在 Cellapp 云端执行用户源码或提供平台编码模型额度。
- 将 `cellapp set agent` 的本机首选项自动升级成远程执行授权。
- 为每种 IDE 或 CLI 保证相同的无人值守执行能力；没有可验证适配器时不启用该执行器。
- 让纯前端 Agent 必须 fork；它继续按首版静态应用和个人模型授权直接访问。

## Decisions

### 1. 分开的设备身份与明确的项目能力

设备通过用户浏览器确认建立独立身份，凭证只用于设备接口并可随时撤销。部署 CLI、MCP、控制台和应用访客的现有凭证不参与任务领取。服务端保存不透明项目 ID、设备 ID、所有者和权限摘要；绝对路径、执行器登录状态及执行所需凭证保留在用户电脑。扩大文件、命令、构建或发布范围须本机确认。选择这一边界是因为远程控制电脑的影响大于部署静态产物；复用部署 Bearer 会让旧客户端隐式拥有新权限。

### 2. 设备主动领取任务，执行器逐个适配

用户从控制台发起任务时先检查设备近期在线和项目授权；离线直接拒绝，不保留会在未来重连时突然执行的新任务。设备主动领取可避免云端入站连接到家庭电脑。任务使用持久 ID、递增序号和有限状态转换；断线后先协调状态，再继续或报告不确定结果。每个受支持成熟 CLI 有单独适配器，核对安装、登录、无界面调用、取消和输出格式。首个适配器在实施前通过真实执行器及 macOS、Windows、Linux 的权限边界验收；不把所有 CLI 假定为相同命令协议，也不强制它们共用同一 OCI 容器。

### 3. 本机独立工作目录与可确认发布

执行前记录基准源码状态和应用发布版本，在独立工作目录完成开发。已有未提交改动不能被重置或覆盖；冲突或无法安全建立工作目录时拒绝任务。输出与日志按大小和敏感字段过滤；上传仅包含明确的静态预览产物。预览使用与正式应用隔离的有期限、需授权来源，不能继承正式访客 Cookie 或数据权限。发布按钮绑定任务、源码/产物摘要和基准发布版本；确认时重新鉴权及比较版本，再复用现有原子部署。这样网络重试不会把过期预览或并发变更发布出去。

### 4. 包版本、fork 副本和执行配置分开

作者发布的包存入私有对象存储，内容经客户端与服务端双重路径、大小、符号链接和明显敏感文件校验；版本与摘要不可变。fork 创建使用者所有的副本及来源引用，不复制作者的模型连接、会话、项目目录或设备凭证。安装到个人设备时由本机能力及权限检查驱动；失败保留旧版。作者版本、使用者副本版本、设备已安装版本与静态应用发布版本分别记录。更新只改变用户主动选择的副本，并在权限扩大时等待设备确认。这避免把作者发布误认为使用者电脑上的自动更新。

### 5. 兼容迁移与分阶段启用

复核现存的试验性迁移 `013`–`015` 与未开放源码，已执行迁移不原位改写；需要字段、约束或版本跟踪时使用新的增量迁移。先部署仍关闭新路由的兼容服务，再逐项启用设备、项目、任务与包接口，并用独立候选环境验证。首版模型 API、CLI 登录、MCP、应用静态发布和访问权保持不变。回滚时关闭新入口并保留任务/副本元数据，不删除已安装副本或现行静态发布。

## Risks / Trade-offs

- [用户本机 CLI 权限过大或登录不可验证] → 逐执行器实测、项目权限确认和无界面能力检查；失败时拒绝，不猜测登录成功。
- [断线与重复消息导致二次执行] → 持久任务 ID、序号、状态协调和独立目录；不确定结果先要求核对。
- [fork 包夹带作者秘密] → 双端校验、敏感文件拒绝和使用者独立配置；不上传本机状态目录。
- [预览泄露正式应用数据] → 独立来源、短期授权、无正式 Cookie 和过期清理。
- [跨系统执行器行为不同] → 每个平台与执行器组合独立验收，不以模拟命令替代真实 CLI。

## Migration Plan

1. 复核旧试验性表和源码，增加必要增量迁移与关闭状态回归；不改写 `013`–`015`。
2. 在隔离候选环境启用设备绑定与项目授权，验证撤销、越权和断线；正式环境仍关闭任务。
3. 接入首个真实执行器和任务生命周期，再交付私有预览及确认发布；验证三系统与跨设备失败恢复。
4. 接入不可变包、fork、安装和权限感知更新；端到端验证作者与使用者隔离后再开放入口。
