# Proposal

## Why

首版已经让用户配置自己的云模型，并让静态 Web Agent 调用模型；本机开发仍由用户已有的编码 Agent 和 Cellapp CLI 完成。要让用户从其他设备发起通用开发任务，并让他人 fork 可运行的 Agent，需要把设备身份、执行权限、源码版本和副本生命周期作为同一条可验收链路设计，避免远程执行与分发各自建立不兼容的权限模型。

## What Changes

- 在用户电脑上复用其已安装、已登录且明确选择的成熟编码 CLI，形成可发起、观察、取消的通用开发 Agent 工作流；Cellapp 不在云端运行用户代码。
- 建立与部署 CLI、MCP 和应用会话分离的设备身份及项目授权。远程任务由设备主动领取；本机按项目授权检查文件、命令和网络边界，离线或撤销时不执行新任务。
- 将任务源码快照、受控构建、私有预览与确认发布绑定到可核验的版本；重复、断线、失败与并发任务不能覆盖用户原有工作或现行发布。
- 让作者发布可核验、不可变的 Agent 包版本，使用者 fork 成独立副本并安装到自己的设备。模型连接、账号、会话、项目路径及本机权限不从作者复制；更新需主动选择，新增权限需重新确认。
- 纯前端 Agent 仍可作为静态应用直接打开并按使用者自己的模型连接授权调用，不要求 fork。此变更与首版个人模型连接和 `cellapp doctor` 的发布验收分离。

## Capabilities

### New Capabilities

- `personal-agent-remote-tasks`：设备身份、项目授权、通用开发任务、断线恢复、私有预览与确认发布。
- `agent-distribution`：Agent 包版本化分享、使用者独立 fork、安装和权限感知更新。

### Modified Capabilities

- `control-api-routing`：为后续设备、任务和包接口增加独立身份与主机路由边界。

## Impact

涉及 Go 控制 API、应用网关、PostgreSQL 增量迁移、私有对象存储、控制台、公开 CLI/Skill 及跨设备验收。实施前复核首版保留但未启用的设备、项目和任务试验性迁移与源码；不改写已执行迁移。首版模型调用、静态发布、应用访问和数据授权应保持兼容。此变更只规划后续能力，不使当前关闭的远程入口提前可用。
