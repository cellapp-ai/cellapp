# Design

## Context

动机见 proposal.md。现有 `apps/console` 是独立 React/TypeScript 前端；根 npm 工作区负责其依赖和检查，公开 CLI/shared 位于 `skills/` 子模块。Go 已实现浏览器登录、`__Host-owner` 会话、设备授权和凭证页面，应用接口使用部署 Bearer 凭证。应用、部署、浏览器会话和凭证已有持久表结构。

浏览器所有者与应用访客使用不同域和授权边界。现有应用密钥重置会更新访问代次，使旧密钥及旧访客会话失效；删除采用墓碑与后续清理。这些行为必须沿用。所有者数据只有身份标识，不存在可展示的头像、姓名、设备名称或完整配额用量接口。

## Goals / Non-Goals

**Goals:** 让管理页面、浏览器 API 和 Go 业务逻辑形成可验收的完整路径；一次请求一次鉴权；可独立开发前端并通过控制域完成真实联调；静态产物与服务端可配套部署和恢复。

**Non-Goals:** 不引入第二个服务端、数据库迁移、浏览器部署凭证存储或新的部署算法。不推导不存在的用户资料、设备元数据、配额统计、发布历史或回滚能力。

## Decisions

### 1. Web 是所有者的管理入口

规格组织统一到 `web-control-plane`：接收旧 `console-frontend` 的三个前端要求及场景，旧能力通过显式退役删除主规格；`apps/web` 源码和验收范围保留。历史变更保留其当时的能力名称，后续不得用旧基础增量重新创建退役能力。

前端迁移到 `apps/web`，包名 `@cellapp/web`，根入口为 `dev:web`、`preview:web`、`lint:web`。保留现有技术栈、字体与品牌资产，通过管理导航、列表和详情重组页面。

UI 路由为 `/login`、`/applications`、`/applications/:id`、`/credentials`、`/device?code=...`。根地址进入登录或应用列表。`/apps` 保留 CLI JSON 接口，避免界面路由覆盖现有契约。登录后默认应用列表；空列表只提供实用的 Skill/CLI 部署指引。应用详情展示实际访问地址、状态和当前发布信息；没有当前发布时明确显示尚未发布。凭证页面称为“部署凭证”，不将凭证记录包装成真实设备列表。

沿用现有英文界面语言，显示品牌 Cellapp，规范文档使用中文。导航、确认、错误与成功反馈都必须有实际行为；会话判断中不闪现私有数据。取消产品标语、特性展示、流程介绍和模拟仪表盘作为首页主体。保留基础落地页不能满足真实管理流程，因此直接替换入口。

### 2. 同源浏览器 API 与 CLI 认证保持独立

新增 `/api/console` 命名空间，由浏览器所有者 Cookie 鉴权。API 返回 JSON，未登录返回 `401 login_required`，不返回登录 HTML。既有 CLI API 继续仅接受原有 Bearer 授权，不为其增加 Cookie 回退。浏览器不读取或保存部署 Bearer 凭证。

| 方法与路径 | 请求/返回及行为 |
| --- | --- |
| GET `/api/console/session` | `{ownerId, authMode}`，仅实际身份标识和当前登录模式 |
| POST `/api/console/logout` | `{loggedOut:true}`，使当前会话失效并清除 Cookie |
| GET `/api/console/apps` | 所有者未删除应用列表，沿用 `id/name/activeDeployment/suspended/url` 字段 |
| GET `/api/console/apps/{app}` | 应用及可空 `release`；当前发布包含 `id/status/createdAt/publishedAt/spa/fileCount/bytes`，不返回存储秘密或历史 |
| DELETE `/api/console/apps/{app}` | `{deleted:true}`，沿用删除事务和墓碑语义 |
| POST `/api/console/apps/{app}/key` | `{key}`，服务端生成 32 字节随机密钥，保存摘要并原子推进访问代次 |
| GET `/api/console/credentials` | 有效且未撤销的 `{id,createdAt,expiresAt}` 列表，不返回凭证明文 |
| POST `/api/console/credentials/{credential}/revoke` | `{revoked:true}`，所有者范围内撤销；已撤销的自有记录可重复成功，其他所有者记录返回 404 |
| POST `/api/console/device/decision` | 输入 `{code,decision:"approved"或"denied"}`，返回最终状态；仅有效 pending 请求能原子转换 |

现有 HTTP 错误结构沿用，新增错误码写入主仓库浏览器契约说明；资源不存在或不属于当前所有者均返回 404，非法输入返回 400，状态冲突返回明确的 409。设备码无效、过期或已处理均返回明确失败，不覆盖已确定状态。

在 `hosting` 内复用/抽取接受显式所有者 ID 的业务操作，CLI 与 Web handler 分别完成各自认证后调用。复用现有事务、锁和资源过滤，不从 Web 导入 CLI 源码，也不复制密钥/删除算法。详情读取保持应用与当前发布一致的快照。保留旧 `/auth/logout`、设备表单 POST、凭证表单 POST、OAuth 回调以及设备创建/轮询契约；GET 管理入口切换为 Web 页面。

### 3. 登录、危险操作与敏感数据生命周期

登录沿用现有 GitHub 流程和仅供本地的开发身份。`return_to` 只接受经过校验的本站相对 UI 路径；设备登录往返保留授权码，不允许外站跳转。设备 URL 只预填和展示请求，不自动批准。退出或任意 API 返回 401 时清空内存中的私有数据和新密钥，转到登录；服务器错误保留可重试错误状态，不伪造空列表。

删除、密钥重置、撤销凭证先显示明确后果并确认，提交期间禁用重复操作。成功以服务端响应为准并刷新对应资源。设备批准/拒绝需要用户主动选择，显示最终结果或过期状态。

新分享密钥只在本次成功操作后的内存中短暂展示与复制，离开页面/退出即清除。不存入 URL、持久存储、日志或错误遥测；普通应用详情无法再次读取。浏览器不能自动重试密钥重置或删除等结果不确定的写操作；丢失响应时说明结果可能已生效，允许用户重新查询或主动再次重置，不能宣称操作失败且未改变状态。剪贴板失败提供手动复制并报告失败，不显示虚假复制成功。

### 4. 控制域安全与资源交付

所有 Web 写请求要求 `Origin` 精确匹配配置的控制域，缺失 Origin 也拒绝；有请求体的接口只接受 JSON 并限制大小。每个资源操作再次查询所有者范围。Cookie 保持 Secure、HttpOnly、SameSite=Lax 和 `__Host-` 约束，不开放携带凭证的跨域请求。访客域不能访问 Web API、会话或控制资源。

Go 提供 UI 页面和本地资源。仅明确的 UI 路由回退到 index；未知 API、未知资源文件和其他路径返回 404，不采用覆盖所有路径的 SPA 回退。HTML 不内嵌私有状态；API 与 HTML 使用 no-store，带内容指纹的公共资源可缓存。Web 的 CSP 限制脚本、样式、字体、图片和请求到本站，禁止嵌入、外部基址及对象；不改变应用网关自己的资源授权/CSP 策略。

选择外部静态产物目录，通过 `WEB_ROOT` 配置，开发默认 `apps/web/dist`。正常服务启动必须验证可读取的 index 与资源目录，缺失时明确失败；迁移和维护命令不要求 Web 产物。根完整构建生成配套的 Go 可执行文件与 `dist/web/`，部署显式指定该目录。相比嵌入 Go，外部目录避免每次前端改动重编译服务端，代价是交付时必须保留两项配套产物。

Vite 独立开发/预览可显示界面和 API 不可达状态，不提供模拟已登录数据。真实联调使用已有本地 HTTPS 控制域和 Go 提供的构建产物，信任本地 CA；不通过关闭 Cookie 安全标志完成验收。根浏览器验收入口先构建 Web；服务单元测试注入静态资源夹具，跨服务验收使用真实构建产物。

### 5. 验证按可观察行为组织

前端检查覆盖类型、lint、构建、320/390/768/1440 px、键盘导航、焦点恢复、减少动态效果与无脚本说明。接口检查使用隔离 PostgreSQL，验证成功、跨所有者、无/过期会话、缺失/错误 Origin、无效设备码、重复决策、并发重置/删除/撤销和响应丢失。通过真实 HTTPS 浏览器验证登录、刷新深链、应用列表/详情、密钥失效、凭证撤销和设备批准/拒绝；同时回归 CLI Bearer、轮询与应用网关。身份/存储替身结果与真实外部 GitHub/对象存储验收分别记录。

## Risks / Trade-offs

- [现有工作区中工程迁移、前端基础和品牌调整尚未完整交付] → 实施前核对已存在的交付状态并保护修改；本变更只承接其最终工程基础，不补写旧记录的验收结论。规格同步按前置基础到本变更的顺序进行，不能随后用旧基础增量覆盖新的控制面约束。
- [服务启动新增静态产物依赖] → 文档、构建和发布命令同时更新；缺少产物启动失败，配套回滚，维护命令保持独立。
- [Cookie 写接口可能引入跨站操作] → 浏览器与 Bearer 分离，严格 Origin、逐资源鉴权及访客域隔离，并验证失败路径。
- [密钥重置响应丢失或并发操作] → 禁止隐式重试，不承诺未发生的结果；以当前代次验证旧密钥失效。
- [没有完整真实身份/存储验收环境] → 保留实际验证缺口，禁止将替身或历史记录作为本轮完整通过。

## Migration Plan

1. 核对前置工程/品牌状态，迁移目录和命令并更新前端规范；不修改公开客户端实现。
2. 实现浏览器 API、静态交付与管理页面，补充主仓库浏览器契约说明和验证入口。
3. 执行相关检查、隔离数据库 race 和 HTTPS 浏览器验收，记录通过/失败/跳过/未执行。
4. 配套部署服务端和 Web 产物，验证静态路由、登录及既有 CLI 路径；必要验收满足后同步规格、归档并按项目规则提交。
5. 回滚使用配套的前一版可执行文件和静态目录；无数据库迁移需要回滚，已发生的密钥/凭证撤销或删除仍保持其业务结果，不因回滚恢复访问权限。
