# Proposal

## Why

Cellapp 的 Web 应用应帮助所有者查看和管理实际托管资源。当前前端只有产品介绍和工作流说明，缺少登录、真实应用数据与管理操作，需要转为连接现有 Go 服务的控制面。

## What Changes

- 将前端迁移到 `apps/web`，包名改为 `@cellapp/web`，运行入口改为 `dev:web`、`preview:web`、`lint:web`，同步根编排、锁文件、前端规范和运行说明。**BREAKING**：移除尚未公开发布的 `apps/console` 开发路径与对应脚本名称。
- 登录后默认进入真实应用列表，提供应用详情、访问地址复制、分享密钥重置及删除；无应用时提供简短的 Skill/CLI 部署指引。
- 接入现有浏览器登录、退出、部署凭证列表/撤销、设备授权批准/拒绝，覆盖未登录、加载、空数据、失败、会话过期和操作确认状态。
- Go 在控制域提供 Web 静态资源及统一使用 `/api/console` 前缀的浏览器会话 API，继续由服务端逐次执行所有者鉴权和同源写请求检查。既有 CLI Bearer 接口、OAuth 回调、设备轮询及应用网关保持兼容。
- Web 采用管理导航、列表、详情和明确的操作反馈；保留现有品牌、字体、配色及可访问性基础，移除标语、工作流展示和预览说明作为首页主体。
- 构建与部署继续由本机 Skill/CLI 执行，本期不增加浏览器上传、发布、回滚、支付、配额图表或管理员跨用户管理。

## Capabilities

### New Capabilities

- `web-control-plane`: 浏览器所有者控制面，包括会话、真实应用管理、部署凭证管理、设备授权、同源资源交付及前端工程、响应式和可访问性要求。

### Modified Capabilities

- `console-frontend`: 退役旧能力并删除其主规格，将三个前端工程与体验要求及全部场景合并到 `web-control-plane`；保留 `apps/web` 源码和行为。
- `repository-workflow`: 将前端源码、命令、文档及完整检查统一切换为 Web 命名，保持前端、Go 服务端与公开客户端边界。

## Impact

- 影响 `apps/web`（由现有前端迁移）、`apps/server/internal/hosting` 的浏览器接口/路由/业务复用、服务启动配置及静态资源组装、根 npm 编排、HTTPS 开发编排与跨服务浏览器测试。
- 新增浏览器专用 HTTP 契约，不扩大现有 `/apps` 等 CLI API 的认证方式；不把部署 Bearer 凭证交给浏览器。会话与持久业务数据复用当前表结构，不新增数据库迁移。
- 更新前端规范、`AGENTS.md`、README、部署和本轮验收说明；品牌显示名沿用 `Cellapp`，技术标识沿用 `cellapp`，项目内容不记载外部参考工程名称或路径。
- 新变更承接已有前端源码与验证基础。旧变更记录保持原验收范围，不将其 15/16 进度视为真实控制面已完成；实施前核对迁移和命名改动的交付状态，保护已有工作。
