# Design

## Context

当前 React 应用每次挂载都请求 `/api/console/session`。侧栏、应用列表和返回链接使用 `<a href>`，因此每次点击都会销毁应用并重新挂载。加载分支还显示 “Sign in to Cellapp”，使已有会话看起来像再次登录。

## Decisions

- 为控制台内部链接保留真实 `href`，仅拦截同标签页、无修饰键的主键点击。通过 History API 更新地址，并以 React 路由状态更新当前内容。新标签页、复制地址、刷新和无脚本行为继续使用浏览器原生链接。
- 将路由状态放在已登录的 `Workspace`，使导航时不重挂载负责会话检查的 `App`。监听 `popstate` 支持浏览器前进后退，并在切换后把焦点移到正文；移动菜单同时关闭。
- 按应用 ID 给详情页设置 key，离开或切换应用时卸载临时密钥与确认状态；设备页按路径和查询参数重新挂载，避免旧授权码残留。
- 初次 `/` 或 `/login` 的已登录返回使用 `replaceState` 后直接渲染 Workspace；无会话时直接显示登录入口。真正过期的业务请求仍通过原有 401 路径清除私有状态并回登录页。

## Verification and recovery

- 正式构建浏览器测试统计会话请求次数，验证多次内部跳转和后退不会重复检查会话；验证详情、焦点、菜单、深链、401 和无脚本场景。
- 若客户端脚本不可用，真实链接仍由服务端明确的页面白名单处理。未部署新前端前可继续运行旧导航行为，无服务端契约变化。
