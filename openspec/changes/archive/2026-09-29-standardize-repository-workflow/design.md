# Design

## Context

动机见 proposal.md。主仓库 Go module 为 `ohmyapp`，根 npm 工作区维护旧 CLI/shared；`tests/browser.e2e.ts` 使用根客户端源码，并直接调用旧入口、读取 `ohmyapp.json`。根单元测试与客户端测试存在重叠。

最新读取发现 `skills/.git` 已存在，origin 为 `git@github.com:cellapp-ai/skills.git`，本地 HEAD 为 `2847115`；它已包含公开客户端、契约、CI 和品牌迁移。本地历史与远程配置不证明提交已推送。主仓库没有 `.gitmodules`，只跟踪 `skills/deploy-static-app/SKILL.md`；该路径在子仓库中是未跟踪目录。不得以初始化新仓库或覆盖检出的方式破坏这些状态。

子仓库公开边界清单尚未允许 `AGENTS.md`。主仓库验证记录称旧变更“未归档”，而归档目录已存在；修正文档状态时保留历史验收事实，不把旧结果当成本轮验证。

## Goals / Non-Goals

**Goals:** 单一客户端实现、保留两个仓库历史、可复现的递归获取、独立客户端发布和完整主仓库联调；规范可在单独克隆子仓库时理解。

**Non-Goals:** 不重命名 Go module 或服务端二进制，不重构 hosting 包，不改变 HTTP/权限/存储协议，不新增数据库迁移框架，不发布 npm 包或创建新的远程仓库，不更改全局 Git/Agent 配置。

## Decisions

### 1. 主仓库固定已有子仓库提交

采用 Git submodule，不采用仅嵌套仓库或 subtree：嵌套仓库不能让主仓库描述获取方式，subtree 则重复保存客户端源码。保留已有 origin 与完整历史，登记 `.gitmodules` 中的 `skills` 路径及 `git@github.com:cellapp-ai/skills.git` 地址，主仓库索引将该路径记录为 mode `160000` 的 gitlink。按 Git 标准子模块布局处理已有 Git 目录，而非重建或删除其 `.git`。

文档提供：

```sh
git clone --recurse-submodules <parent-url>
git submodule update --init --recursive
git pull --recurse-submodules
git config submodule.recurse true
```

最后一项是开发者主动执行的仓库本地配置；`.gitmodules` 不会自动为所有克隆设置普通 pull 的递归行为。新建子模块或未初始化检出需先执行初始化。远程 SSH 地址要求读取权限与 SSH 认证，不能承诺任何环境均免配置获取。日常使用固定提交而非 `update --remote`；修改子仓库时先切到开发分支，避免将工作遗留在 detached HEAD。

### 2. 客户端统一到子仓库，主仓库保留编排

以现有 `skills/packages/` 为唯一客户端源码，先比对根实现及测试，迁入尚未覆盖的业务回归再删除重复代码。根 `package.json` 保持 private，移除旧客户端 workspaces、bin 和包发布清单；保留运行主仓库浏览器验收需要的 tsx、类型、TypeScript 和 playwright-core 依赖。子仓库独立使用自己的 package.json、锁文件及 dist 输出。

根 `npm run cli -- ...` 代理到子仓库 CLI，透传参数；`typecheck` 检查子仓库与主仓库验收脚本；`build` 构建子仓库后构建 Go 二进制；`test` 运行子仓库单元测试和服务端测试。采用根 scripts 下一个小型编排入口检查子模块是否已初始化、透传参数、顺序执行并传播失败码，而非在两个仓库之间共享 npm 工作区。缺少子模块时给出初始化命令，不自动修改用户配置。

依赖安装明确分为主仓库 `npm ci` 和 `npm --prefix skills ci`；不在 npm 安装生命周期中隐式拉取仓库或联网安装另一套依赖。根 tsconfig 去掉旧 packages 源入口并调整联调脚本检查。CLI 的 npm pack 与安装说明改从 skills 执行，根不再生成旧 CLI 发布包。

客户端单元测试归 `skills/tests/`。`tests/browser.e2e.ts` 保留作为主仓库跨服务验收，更新源码引用与子进程入口为 `skills/packages/...`，读取 `cellapp.json`；通过子仓库迁移测试继续验证旧 `ohmyapp.json`/凭证兼容。Go 浏览器测试的脚本定位、工作目录和依赖解析一起检查，确保用的是统一客户端。原部署 Skill 与 canonical `skills/skills/cellapp-deploy` 比对后合并必要说明并移除旧路径；本轮迁移删除仅限已核对的重复文件。

### 3. 两级规范分工

主 `AGENTS.md` 维护单服务架构、目录树、依赖方向、扩展准则、跨仓库契约、OpenSpec 流程、集成验证和交付规则。子 `AGENTS.md` 维护客户端模块职责、TypeScript strict/ESM 约定、HTTP 和本地状态兼容、独立验证与打包、公开边界以及 standalone 开发流程。

根规范覆盖 Go gofmt、错误处理、超时/取消、参数化 SQL、事务与并发、权限和秘密保护；新增职责先在现有模块内扩展，拆包须有实际依赖/生命周期依据，不预建空目录。子规范不复制主仓库私有架构或运维内容，也不要求单独贡献者拥有主仓库。

设计 → 确认 → 开发 → 测试 → 归档 → commit 是完成流程。业务/架构/协议变更通过主仓库 OpenSpec 规划；独立子仓库贡献通过其可访问的设计/审查记录执行同等阶段，无需把主仓库 openspec 拷入公开仓库。纯文档修正可以用简短说明与事实校验完成各阶段，不强制编造产品规格。范围内不重复授权，架构或行为扩大须确认受影响设计。不得用规范宣称尚未执行的验证或提交。

### 4. 公开边界与可获取交付

允许清单只新增公开客户端 `AGENTS.md`，保留其他禁止项并同步相关边界检查。无需为文档新增镜像内容的测试，现有边界检查必须通过。

跨仓库完整交付先通过相关检查，同步规格并归档；然后只提交本次客户端文件，推送到现有远程并验证目标提交可获取，最后提交主仓库归档、文档、源码调整与 gitlink。如果推送不可用，保留本地工作、明确阻塞，不能提交指向不可获取对象的主仓库完整交付版本。推送范围依用户当时授权执行，不把 npm 发布包含在 commit 中。

## Risks / Trade-offs

- [已有嵌套 Git 与未提交文件] → 转换前记录两仓库状态及旧 Skill 内容，保留已有对象和历史；禁止重置、强制覆盖或批量暂存无关工作。
- [公开允许清单拒绝规范或旧 Skill] → 精确放行 AGENTS，先合并旧 Skill 必要内容，移除已确认重复路径后执行边界检查。
- [联调仍引用旧 CLI 或状态路径] → 更新浏览器脚本与 Go 启动路径，执行真实数据库/浏览器相关验收；不能以编译成功代替联调。
- [子仓库新版本不兼容服务端] → 主仓库固定提交，结合现有契约和跨服务测试验证升级，保留旧本地状态兼容。
- [主仓库指向远程不可获取提交] → 子仓库先推送并验证，再提交主仓库；完整远程递归验收需要读权限，无法执行时明确验证缺口。
- [数据库或浏览器环境缺失] → 明确标注集成检查跳过或未执行；尚未满足必要验收时不归档为完成。

## Migration Plan

1. 记录两仓库状态与子仓库提交、远程，保留当前未跟踪/已跟踪旧 Skill；比对两套客户端及测试。
2. 在客户端开发分支补齐回归覆盖，创建公开 AGENTS，调整边界清单；合并并退役旧 Skill，验证独立客户端。
3. 主仓库移除经比对的重复包和单元测试，调整编排、锁文件、tsconfig、联调脚本与安装文档，创建根 AGENTS。
4. 保留现有子仓库历史，将主索引中的旧 Skill 跟踪替换为 `.gitmodules` 和 gitlink，使用标准子模块目录管理；不为拉取便利改写子仓库远程或用户全局配置。
5. 执行主/子检查及浏览器集成，在临时检出验证初始化、递归克隆与两版 gitlink 间的递归更新；本地 fixture 验证行为，另以远程读取验证实际目标提交可获取。
6. 审查文档事实及变更差异，完成 OpenSpec 验证、主规格同步和归档；按子仓库先、主仓库后的顺序交付。

回退保留两仓库提交，主仓库通过正常 revert 恢复旧目录/入口和对应 gitlink，按记录复原子仓库匹配状态，不删除已有 Git 历史；转换前备份用于恢复未提交文件，不以强制重置回退。
