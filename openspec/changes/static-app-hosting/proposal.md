# Proposal

## Why

AI 已经能快速生成个人网页和前端工具，但用户仍需要自己处理构建、部署、域名和访问控制，才能在不同设备上使用。提供由 Skill 驱动的免费静态应用托管，让用户在 AI 对话中完成发布，并通过应用独立分享密钥访问。

## What Changes

- 提供部署 Skill 及其命令行客户端，在本地构建项目，仅上传静态产物；兼容普通 HTML 和可导出静态文件的前端项目。
- 首次使用通过浏览器设备授权识别应用所有者，后续复用本机部署凭证。
- 发布后返回稳定 HTTPS 地址和每个应用独立的分享密钥；默认密钥访问，本期不提供公开访问开关。
- 提供应用创建、列表、重新部署、密钥重置和删除能力；更新采用完整版本切换，失败保留上一版本。
- 对页面、静态资源和 SPA 路由统一进行访问验证，并隔离不同应用的浏览器来源。
- 免费提供有额度限制的托管，覆盖应用数量、文件大小、存储及流量；不引入付费或计费流程。
- 不包含用户后端执行、平台云端构建、应用数据库、跨设备数据同步、自定义域名或应用内多用户权限。浏览器本地数据仍仅属于该浏览器。

## Capabilities

### New Capabilities

- `deployment-authorization`: 所有者登录、设备授权、本机部署凭证和应用管理权限。
- `skill-deployment`: 本地构建、产物校验、上传及可重复的部署流程。
- `static-app-lifecycle`: 静态应用、版本发布、稳定地址、删除和免费额度。
- `app-key-access`: 应用独立密钥、访问会话、资源保护与应用来源隔离。

### Modified Capabilities

无。项目尚无现有能力规格或实现。

## Impact

新增控制面 API、浏览器授权页面、静态资源访问网关、元数据存储、私有产物存储，以及 Skill/CLI。需要配置 HTTPS 控制域名、独立应用托管域名及通配符解析和证书。实现与测试从空项目开始；本 change 只生成规划文件，技术选型和运行参数见设计文档。
