# Design

## Context

见 [proposal.md](proposal.md)。当前 Go 单服务管理控制元数据、浏览器身份、应用网关和静态发布；PostgreSQL 记录控制状态，私有对象存储保存产物，应用数据在独立数据库。静态发布由用户本地构建，经 CLI 或 MCP 上传，服务端只校验与分发产物。`/_cellapp/me` 和数据接口使用应用会话，控制台使用控制域会话；SDK 固化应用 API 版本。现有 MCP 的方向是外部 Agent 调用 Cellapp，不提供向用户电脑下发任务的通道。

## Goals / Non-Goals

**Goals:**

- 让云端 OpenAI 兼容模型连接可由个人用户管理，并在应用模型调用中保持用户身份与撤销边界。
- 让纯前端 Agent 在既有静态应用域内调用模型，让用户已有的编码 Agent 引导其在本机准备 Cellapp 开发环境。
- 通过无模型、只读的 `cellapp doctor` 和明确的 `cellapp set agent` 选择提供可检查、可手动恢复的本机设置流程；登录与本地权限由用户控制。

**Non-Goals:**

- Cellapp 云端执行用户程序、构建项目或托管常驻业务 Agent。
- 本机模型地址、Anthropic 原生接口、模型费用代收或平台 Token 额度。
- 将 MCP 作为本地任务通道，或把现有部署凭证升级为设备控制凭证。
- 设备配对、从手机或其他电脑远程编码、预览发布、通用开发 Agent 与本地 Agent fork；统一由 `add-agent-development-and-fork` 处理。
- 首版安装或运行内置 Boot Agent、替用户安装/登录其他编码 Agent，或为了本机引导要求设备常驻在线。

## Decisions

### 1. 模型连接由 Cellapp 管理，模型调用采用受控适配层

连接记录归属于全局平台用户，保存显示名称、固定 API 基址、测试模型 ID、该模型的能力测试结果和加密密钥；未填写测试模型 ID 时从供应商模型列表选取，获取失败可手动填写。测试结果不推断为连接下所有模型的能力；应用域只出现不透明连接选择与授权状态，不暴露基址或密钥。控制台新增创建、测试、更新、删除与应用授权管理。服务端增加独立模型调用边界，先实现 OpenAI Chat Completions 的文本、SSE 流式输出与工具调用；不把任意供应商路径、请求头或代理功能开放给应用。

第一版由 Go 服务内的适配层调用上游，保持 Cellapp 的授权和错误契约。可在适配层之后评估 LiteLLM 或 Bifrost，但只有在其动态个人地址/密钥、流式工具调用、隔离和运维成本通过候选验证后才引入；产品接口与数据库不依赖网关专有虚拟密钥。相较第一版直接部署通用网关，这避免再维护一个外部服务的用户身份和密钥模型。新适配器的边界保留以后切换后端或增加 Anthropic 原生适配的空间。

公网地址只允许 HTTPS，规范化基址后由服务端拼接固定模型路径。解析、连接和重试均拒绝本机、链路本地、私网、云元数据及保留地址；禁用重定向，对实际连接 IP 再校验，限制 DNS/连接/首字节/总时长、请求和响应大小。除必要协议字段外不透传应用自定义请求头。密钥由独立加密材料保护并支持轮换；日志只保留连接 ID、请求 ID、结果类别与可用用量，不保留密钥和默认不保留提示词。连接测试在用户操作时运行，并按文本、流式、工具能力分别报告；能力声明不是对未来供应商可用性的永久保证。

### 2. 使用者按供应商连接授权，模型选择保存在当前浏览器

应用以同源 `/_cellapp/v1` 作为模型 API base URL。第一版实现 `GET /models` 与 `POST /chat/completions` 的 OpenAI 协议形态；后续增加的 Responses 路径是 `POST /responses`，而非单数 `/response`。`/v1` 是该模型接口的固定协议版本，不依赖额外 `?v=`；网页其他运行时接口继续按原有版本规则。只承诺已实现的 Chat Completions 文本、流式与工具调用子集，不把未实现的 OpenAI 能力宣称为一比一兼容。

每位使用者可为同一应用授权多个自己的供应商连接，授权由控制域确认并按使用者、不可变应用 ID、连接 ID 分别记录。`GET /models` 只列出当前应用已获授权连接的模型并集；每个返回 ID 带稳定的连接命名空间以避免不同供应商模型 ID 冲突，`owned_by` 显示供应商连接名称。模型目录在应用请求时从供应商 `GET /models` 有界获取；失败时仍展示用户手动填写的模型 ID。服务端不将供应商地址、密钥或未获授权连接暴露给应用。SDK 负责授权入口和选型弹窗；选择偏好仅写入当前浏览器的应用来源本地存储，其他浏览器需重新选择，Cellapp 服务端不保存“当前模型”。

`POST /chat/completions` 请求使用 OpenAI 的 `model`、`messages`、可选 `tools` 和 `stream` 字段。每次请求中的 `model` 是路由必需信息，会到达 Cellapp 服务端并计入相应连接的用量；“本地保存选择”仅表示不额外同步或持久化默认模型。服务端根据应用会话和命名空间重新检查连接所有权与应用授权，不信任应用脚本的本地选择；同一获授权连接下可调用任意模型 ID。没有授权时返回可识别错误和控制域授权页地址。应用脚本与 SDK 在同一来源运行，SDK 弹窗不是安全边界；按连接授权代表应用代码可调用该连接下的其他模型，界面须向使用者明确说明。匿名页面可以展示，但模型调用要求登录和应用准入。

上游调用先检查授权、连接能力和配置的每用户/应用请求上限，再有界转发；并发限制与请求频率是成本保护，不宣称替用户控制供应商账单。SSE 透传只接受已声明事件形态，缓冲有上限，客户端断开时取消上游请求。服务端记录请求数、状态、上游返回的 token 数据或“未知”，不从缺失的流式最终块推断精确费用。工具调用结果只作为数据返回；工具的文件、应用数据或其他动作由对应本地客户端或前端按既有权限执行。应用作者的代码仍可能把使用者输入和它有权读取的数据发给模型，因此授权界面清楚展示数据流向。

### 3. 首版：用户现有 Agent 引导与 `cellapp doctor`

首版不启动 Cellapp 自带的 Agent 循环。公开设置指令或 Skill 面向用户已经安装并可使用的编码 Agent，指导它调用 Cellapp CLI 检查环境、完成浏览器登录、按用户项目的真实构建方式准备静态产物并部署；不支持 Skill 的 Agent 可读取同一公开 Markdown 指令。没有编码 Agent 时，用户按文档在终端手动执行相同步骤。此引导不依赖个人模型连接：模型连接只服务于已发布应用中的使用者模型调用。现有 Agent 的账号、订阅与工具权限由用户及该 Agent 自身管理，Cellapp 指令不是其命令执行权限边界；Cellapp CLI 继续逐次校验自己的登录、项目与部署操作。

`cellapp doctor` 是无需登录或模型即可启动的只读命令。它报告当前操作系统、Node.js 与 npm/CLI 可用性、Cellapp 本地配置状态，以及受支持编码 CLI 的安装、版本和可确认登录状态；仅在提供 `--project` 时检查该目录存在性、可读性、项目关联、构建脚本与静态输出线索，不执行构建，也不遍历无关目录。检查 Cellapp 控制域 HTTPS 连通和当前登录时使用有界只读请求；离线、凭证缺失或状态命令不可靠时报告“无法确认”或“需登录”，本地检查仍继续。由于 CLI 本身需要 Node.js，完全没有 Node.js 的设备应由公开指令给出安装前置步骤。输出区分通过、需处理和无法确认，并附修复建议；JSON 输出供外部 Agent 使用，默认结果不包含密钥、Cookie、提示词或其他 Agent 的凭证内容。

CLI 发现仅检查 `PATH` 和明确支持的安装位置，以已验证的官方状态命令判断登录；不扫描凭证文件。`cellapp set agent <名称>` 允许用户或其本地 Agent 选择受支持的已安装编码 CLI，例如 `cellapp set agent codex`。命令在保存本机首选项前校验名称与可执行文件，不接受任意 shell 字符串、附加命令或未经验证的路径；选中后由 `cellapp doctor` 展示状态和缺失的登录步骤。选择首选项不启动编码、不执行登录或安装，也不构成远程任务、项目文件或发布权限的授权。选择保存在本机私有配置中，不写入项目产物或同步为平台账号的默认 Agent。

首版不要求设备配对、设备心跳、云端项目权限摘要或本机常驻进程；控制台不把“我的设备”作为本机设置入口。已开发的 mini-SWE 运行时、Boot 模型会话、设备与远程任务试验性入口须在实施阶段移除或保持不可访问，不能仅凭路由显示“暂不可用”就当作首版能力交付。已执行的迁移版本不可原位改写；实施时核对实际部署状态，必要时用增量迁移保持兼容，避免删表造成数据损失。

通用开发 Agent、设备身份、主动任务通道和 fork 的权限模型由后续 `add-agent-development-and-fork` 共同设计。Codex、Claude Code、Cursor 等 CLI 在本变更中仅作为用户自己运行的引导者或本机工具，不被 Cellapp 自动委托执行远程任务。

## Risks / Trade-offs

- [自定义公网 API 地址被用于请求内网或窃取密钥] → 固定上游路径、HTTPS、公网 IP 校验、禁跳转、连接时二次校验及隔离的出站网络策略；以恶意 DNS/重定向服务验收。
- [OpenAI 兼容接口细节不一致] → 仅承诺 Chat Completions 子集，逐项连接测试并显式呈现能力；流式或工具不兼容时返回明确错误。
- [第三方 Agent 用用户的模型连接发送敏感内容或消耗额度] → 逐应用授权、用户可撤销、默认限额与请求记录；明确应用可见数据仍由应用自身行为决定。
- [公开指令被误认为能约束用户 Agent 的工具权限] → 指令只提供步骤；高权限操作仍依赖现有 Agent 的本机权限提示和 Cellapp CLI 的授权检查，不因 `set agent` 选择而开放远程执行。
- [诊断意外修改环境或泄露本机秘密] → `doctor` 只读、有界检查，不自动安装、登录、构建或输出凭证；离线和不可靠状态明确标为无法确认。
- [CLI 发现误读用户秘密或误判登录状态] → 只检查限定位置和受支持的状态命令，不读取凭证文件；不支持状态检查时明确显示未知。
- [跨仓库交付顺序复杂] → 服务先兼容新客户端，再发布 `skills` 客户端及文档；候选环境验证两端版本及回滚路径。

## Migration Plan

1. 先部署兼容旧客户端的模型连接与应用授权；保持现有静态发布、CLI 与 MCP 路径可用，关闭首版不需要的设备、Boot 模型会话与远程任务试验性入口。
2. 在隔离环境验收公网兼容供应商、模型流式调用、跨用户/跨应用权限、恶意地址拒绝和密钥轮换，交付纯前端 Agent 的控制台与 SDK 体验。
3. 交付公开本机设置指令/Skill、`cellapp doctor` 与 `cellapp set agent`；在 macOS、Windows 和 Linux 验证无模型、无登录、未安装 Agent、状态未知、项目检查、选择切换及手动恢复。核对现有试验性迁移的兼容状态，移除 mini-SWE 依赖和不属于首版的可访问入口；首版不启用设备绑定、远程任务、预览发布或本地 Agent 包安装。
4. 按服务端、路由、客户端的兼容顺序发布；回滚保留向后兼容的新增表与既有静态发布，不删除用户模型连接。通用开发 Agent 与 fork 在独立后续变更中验收。
