# 前端设计规范

适用范围：`apps/web` 的前端页面、组件、交互及品牌资源。设计验收目标与实际实现状态须区分，服务端及 CLI 行为不由本规范定义。

## 设计方向与品牌

品牌名称遵循 [品牌规范](brand.md)：使用 **Cellapp** 或 **cellapp**，不得使用驼峰写法。该命名规则同样适用于页面标题、辅助技术文字及资产说明。

使用深色背景、荧光绿主强调、蓝色辅助强调和清楚的工程信息层级。控制台优先帮助用户辨认内容与下一步，标题、操作与数据使用适合管理界面的密度；装饰服务信息层级，避免大量渐变、阴影、浮层、重复卡片和连续动画。

**现状**：Web 使用深色管理界面，尚无主题切换。英文文案保持简短、具体，示意和预览标识靠近相关内容，不暗示未实现的成功结果。工程细节留在开发文档，仅将帮助产品用户做决定的信息放入界面。

品牌资产位于 [`apps/web/public/logos/`](../../apps/web/public/logos/)，通过 `/logos/<文件名>` 访问。

| 资产 | 用途 |
| --- | --- |
| `cellapp-landscape.svg` / `cellapp-landscape-light.svg` | 横向字标，493 × 100，深色背景用白字、浅色背景用黑字 |
| `cellapp-square.svg` / `cellapp-square-light.svg` | 方形图标，1024 × 1024，分别黑底白标、白底黑标 |
| `cellapp-portrait.svg` / `cellapp-portrait-light.svg` | 400 × 440 竖向图标与字标，透明背景 |
| `cellapp-square.png` / `cellapp-square-light.png` | 对应方形 SVG 的 1024 × 1024 位图副本 |

SVG 是可编辑来源，PNG 由对应 SVG 渲染生成。Logo 的 Michroma 字形已转为矢量轮廓，不作为正文运行时字体。不拉伸、旋转或自行重排 Logo，不用普通文本替代矢量字标。横向与竖向背景透明，方形版自带底色；保持背景对比，建议至少 12 px 净空。

桌面导航横标宽 180 px，小屏宽 156 px，最窄布局可收缩至 132 px，保持原比例；品牌链接至少 44 px 高并提供可访问名称。方形 SVG 用作 favicon。更新来源时检查全部展示与导出副本。

## 颜色与字体

| CSS token | 值 | 用途 |
| --- | --- | --- |
| `--color-ink` | `#090d18` | 页面背景、亮按钮文字 |
| `--color-panel` | `#111827` | 内容面板 |
| `--color-paper` | `#f5f7f2` | 标题与主要文字 |
| `--color-muted` | `#9ba5b7` | 次级文字 |
| `--color-line` | `#293142` | 结构分隔与常态边框 |
| `--color-lime` | `#b6ff5c` | 主操作、焦点及选中强调 |
| `--color-blue` | `#8199ff` | 辅助标签 |

主按钮采用 lime 背景和 ink 文字，次操作采用透明背景和可辨识边框。line 适合非关键分隔，交互控件边界须单独检查对比度。状态同时提供文字或语义标记，不单靠颜色表达。

正文、标题和按钮使用 Space Grotesk 400 / 500 / 600 / 700，代码与短标签使用 DM Mono 400 / 500，均由本地依赖打包并采用 swap。当前仅 Latin 字形，中文等语言回退到系统字体，新增语言须检查真实排版。

控制台 h1 为 `clamp(2rem, 4vw, 3rem)`，行高 1.15；h2 为 `1.25rem`，行高 1.4；正文行高 1.7。长标题检查换行，不使用营销大标题作为所有页面的默认。等宽字体限于短工程信息，不铺满正文。

## 布局与形状

容器最大 1180 px，桌面两侧 32 px，小屏 24 px，最窄布局 16 px。当前桌面使用 260 px 导航栏与内容区域，800 px 及以下折叠导航、列表改为适合小屏的布局；菜单展开后自适应高度。

间距复用 `--space-*` 的 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 px 尺度。主次按钮圆角 5 px、面板 8 px，保持克制圆角与分隔线；管理信息不套用大段营销留白或倾斜终端装饰。

主要内容按标题、说明、操作组织。数据表格和代码在自身容器内滚动，空、加载、错误、禁用状态按真实业务设计，并提供解释或恢复入口。只创建有实际用途的状态，不预先展示模拟数据。

## 交互、响应式与可访问性

- 主要操作文字说明结果，hover、focus 和选中状态可辨识。焦点使用 2 px lime outline、4 px offset 或同等可辨识方案。
- 移动菜单具备展开、关闭和 Escape 行为，辅助技术状态同步；管理链接到达真实页面，跨页导航提供当前页语义。
- 动效约 0.2 秒且克制；减少动态效果时停用非必要动画、平滑滚动和位移。
- 至少检查 320、390、768、1440 px，并补查 800 / 801 px。页面不允许整体横向溢出，长标题、链接和内容保持可读。
- 界面有主要 h1、main、导航名称、跳过正文入口和可感知反馈；装饰图像使用空 alt，有信息图像提供恰当描述。
- 以 WCAG AA 为目标：普通文字至少 4.5:1，大号文字至少 3:1；关键控件边界和状态也需可辨识。目标不是完整合规认证声明。
- 新控件优先保持至少 44 × 44 px 触控目标，不仅靠 hover 提供信息。键盘可以到达并操作主要交互，隐藏菜单不留有可聚焦项。
- JavaScript 不可用时提供有意义的说明，不显示假管理界面。新增中文、长内容及 200% 缩放时人工检查回退字体、布局和阅读顺序。

## 前端设计验收

- [ ] 品牌比例、色彩与本地字体符合基线，无隐式远程字体请求。
- [ ] 主次信息清楚，文字与操作符合真实能力。
- [ ] 桌面、小屏、断点两侧、长内容和缩放无整体溢出。
- [ ] hover、focus、菜单、键盘与无脚本说明可用。
- [ ] 减少动态效果和辅助技术语义已检查。
- [ ] axe 及人工视觉、焦点检查分别记录结果。

**待改进**：跨浏览器兼容性与视觉快照差异门禁尚未覆盖，后续页面应逐步补充，不将当前界面验收等同于完整产品认证。
